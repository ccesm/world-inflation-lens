# V0.13 — Data contracts, freshness and system status

This release adds status infrastructure to the validated snapshot system. It does not add macroeconomic observations, redesign the homepage, consolidate V1.0 logic or implement a Signal Engine.

## Incremental metadata contract

`src/data/seriesRegistry.js` owns bilingual series names, evidence maintenance type, research status, causal role, reviewed citation overrides and freshness policies. `src/data/seriesContract.js` adapts existing snapshots without changing observations, units, seasonal adjustment or original provenance. Existing ingestion specifications remain authoritative for parsing and measurement definitions: this is a compatibility layer, not a second ingestion pipeline.

The contract represents publisher separately from distributor, source URL, units, frequency, adjustment, geography, data type, research status, observation/source/retrieval semantics, release schedule, freshness policy and citation/use note. Maintenance types are `AUTOMATIC`, `MANUAL_REVIEWED`, `FIXED_VINTAGE`, `STATIC`, `DERIVED` and `PLANNED`. Missing metadata yields `UNKNOWN`, never inferred integration from a page's existence.

Natural gas now links to the already-integrated `MHHNGSP` snapshot. Cross-module verification rejects an indicator marked planned if the same series is integrated. There is no new natural-gas download.

FRED is a distributor, not a blanket license. The parser preserves individually reviewed use notes and has a neutral citation default. T5YIFR retains its source's copyright/citation requirement. Existing raw snapshot notes are preserved in Git; the frontend compatibility adapter corrects the former generic public-domain assertion, and future refreshes write the corrected note.

## Dates are different concepts

| Field | Meaning |
| --- | --- |
| observationDate | Period represented by the measured value; quarterly anchors display as quarters |
| sourceUpdatedAt | Source publication/vintage, or FRED distributor update; not necessarily original publisher release |
| retrievedAt | When the snapshot was downloaded/imported |
| checkStartedAt | Start of this site's attempt |
| checkCompletedAt | Recorded after candidate build and full verification succeed, or when a failed attempt ends |
| lastSuccessfulCheck | Last validated check completion; older ledgers lack completion and remain explicitly labeled legacy |
| deployedAt | Time recorded in the deploy job only after Pages deployment succeeds |
| appVersion | `package.json`, injected by Vite |
| codeCommit | Code commit that began the workflow |
| snapshotCommit | Exact commit containing the validated economic snapshot used for the final build |

Month/date/quarter precision is retained. Recognized FRED update timestamps retain the original text plus an ISO instant; unrecognized text is not guessed. Existing historical timestamps are not backfilled or reinterpreted.

## Release-aware freshness

Normal source calendars:

- [H.15](https://www.federalreserve.gov/releases/h15/): weekday 16:15 America/New_York; DGS10/DFII10 conservatively expect the preceding Treasury business-day observation. Federal holidays and normal Treasury market closures are accounted for.
- [H.10](https://www.federalreserve.gov/releases/h10/): Monday 16:15; prior business-week observations. A Monday holiday moves publication to the next business day. Daily observations do not imply daily publication.
- [H.4.1](https://www.federalreserve.gov/releases/h41/): Thursday 16:30; Wednesday balance. A federal holiday shifts publication to the next business day.

Four hours of distribution grace is a site assumption, not an official promise. Exceptional closures and source delays can differ. Passing an expected window can produce `STALE`, but never proves the provider actually published. `SOURCE_UPDATED_NOT_YET_CAPTURED` requires a validated source probe with newer metadata/coverage.

For other automatic series, conservative lags are measured from the end of the observed period: generally 75 days monthly, 150 quarterly, 455 annual, 16 weekly and 7 daily. CPI has 50 days; wages/employment 45; PCE/M2 65; commercial electricity sales 125. These are disclosed review prompts, not invented release dates. Exact rolling BLS/BEA release calendars are not automatically scraped in this release.

States include `CURRENT`, `CHECKED_NO_NEW_RELEASE`, `WAITING_FOR_EXPECTED_RELEASE`, `SOURCE_UPDATED_NOT_YET_CAPTURED`, `STALE`, `REFRESH_FAILED`, `MANUAL_REVIEWED`, `MANUAL_REVIEW_REQUIRED`, `FIXED_VINTAGE`, `STATIC`, `DERIVED`, `PLANNED` and `UNKNOWN`.

Manual facts and SIPRI do not inherit daily checking. Their original review/import dates remain visible; a conservative 400-day review reminder is separate from observation freshness. CBO always displays its separately reviewed fixed vintage, publication and import dates; no daily stale rule is applied. Static history is not freshness-scored. Derived indicators require checking their inputs separately.

## Schedule

One check daily at **17:40 America/Los_Angeles**, using GitHub's timezone-aware schedule. This is 20:40 Eastern, after normal H.15/H.10/H.4.1 releases and the four-hour distribution buffer. It handles DST through IANA timezones. Weekend checks can legitimately find no change. [GitHub can delay scheduled workflows](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule); no exact execution or same-day-data guarantee is made.

## Independent public status

The `status` workflow job runs after build, deployment and notification outcomes. It publishes only `system-status.json` to the separate `system-status` branch through the GitHub API. This branch contains no application files or economic snapshots and does not trigger the main-branch deployment workflow. It uses the existing repository workflow token, not a new frontend secret.

Sources / Data Health reads this one public JSON from GitHub Raw, with timeout and an unavailable/unknown fallback. Economic data still come exclusively from bundled validated snapshots; no browser macro API or runtime backend is introduced. The UI distinguishes the browser's build from the latest recorded deployment. An older workflow outcome cannot silently overwrite a later one. The small status artifact has an explicit whitelist: no email address, credential, secret name, provider body or arbitrary error text is published.

The refresh writes a separate safe `.refresh/check.json` even on parser/build failure. The workflow uploads it with `always()`. The production application is not redeployed on failed refresh: previous economic snapshots remain intact, while the independently published outcome can show failure. Download/publication/setup failures may leave status unknown; a cancelled runner may fail to publish at all. These limits remain visible through the Actions link.

Deployment success is only recorded from the successful deploy job and its completion timestamp. A successful data check followed by deployment failure preserves the previous successful deployment identity. Missing prior completion timestamps remain unknown, not derived from the ledger's old start timestamp.

Mail states: `ACCEPTED_BY_GMAIL`, `SKIPPED_NOT_CONFIGURED`, `FAILED_AUTH`, `FAILED_TRANSPORT`, `FAILED_CONFIGURATION`, `UNKNOWN`, `NOT_REQUESTED`. SMTP acceptance never proves inbox placement. Missing configuration can yield a green mail job but the public state explicitly says skipped. A failed email cannot erase a successful deployment.

## Verification and limits

Behavioral tests cover release timing, weekends, federal/market holidays, DST, distribution grace, mixed frequencies, unknown metadata, unchanged checks, validated newer source probes, manual/fixed/static evidence, integrated/planned contradictions, individual rights notes, shared bilingual names, version injection and sanitized independent outcomes. The isolated real refresh test covers failure reports, unchanged/changed completion and full rollback of economic files. The actual status publisher also runs against a mock GitHub API, checking status-only branch creation, permission failure, safe serialization, retained production identity and mail/deployment independence. These tests send no real mail or API requests. Existing CBO, dollar, AI, Digital Money, External Shocks, routing, CSV and Pages checks remain gates.

Local browser checks cover 360/390/1280-pixel widths in both languages and both themes, with no horizontal page overflow or browser errors. Simulated refresh/authentication failures retain prior successful timestamps; an unavailable public status endpoint preserves bundled data and clearly shows unknown status. These simulations do not certify the first production status publication.

Public status publication must be verified in a real post-merge GitHub run; local tests do not prove repository permissions or GitHub Raw cache timing. Exceptional release calendars, comprehensive vintage reconstruction, runtime performance work and V1.0 causal consolidation remain future work.

`npm run build` and the complete `npm run verify` pass for this checkpoint. Vite still reports existing large economic-data/application chunks; this release does not suppress the warning or introduce unrelated bundle restructuring.
